# 公司新聞蒐集 → 訪視報告「近兩年相關新聞」產生器

輸入目標公司名稱，自動以關鍵字蒐集近兩年新聞、抓取全文，並輸出成與
`115_A-I-001_54955208_台灣禾邦電子有限公司.doc` 完全相同版面的 Word 檔。

## 檔案

| 檔案 | 用途 |
|---|---|
| `crawler.py` | 新聞蒐集核心：關鍵字展開、Google News／鉅亨網檢索、網址還原、全文擷取 |
| `docbuilder.py` | Word 產出：重建原始 .doc 的五個樣式、TOC 目錄欄位、頁碼、.doc 轉檔 |
| `history.py` | 歷史紀錄：存檔、列表、載回、刪除、ZIP 匯出 |
| `smoke_test.py` | 冒煙測試：實際執行 app.py 並檢查例外與模組版本一致性 |
| `main.py` | 命令列版 |
| `app.py` | 網頁版（Streamlit） |
| `requirements.txt` | 相依套件 |

## 安裝

```bash
pip install -r requirements.txt
```

## 命令列用法

```bash
python main.py --company 台灣禾邦電子有限公司 --year 115 --case A-I-001 --tax-id 54955208
```

常用參數：

| 參數 | 說明 |
|---|---|
| `--keywords 華新科,焦佑衡` | 額外關鍵字（集團名、董事長、股票代號、品牌名） |
| `--official-url https://www.walsin.com/` | 公司官網，會一併抓官網最新消息 |
| `--priority-domains money.udn.com,ctee.com.tw` | 自訂第一優先來源網域 |
| `--priority-boost 180` | 優先來源的新鮮度加權天數；設 0 = 純依日期，不分來源 |
| `--related 母公司,轉投資公司` | 母公司（投資人）與相關企業，一併檢索並標明對象 |
| `--topic-boost 120` | 命中關注議題的加權天數；設 0 = 不加權 |
| `--require-topic` | 只保留命中關注議題的新聞（預設不過濾） |
| `--other-quota 0.25` | 保留給未命中議題新聞的名額比例；設 0 = 不保留 |
| `--years 2` | 蒐集近幾年，預設 2 |
| `--max 15` | 最多納入幾篇 |
| `--outdir .` | 輸出資料夾 |
| `--json out.json` | 另存原始資料 |
| `--from-json out.json` | 由既有 JSON 重新產檔（人工挑選／修訂後再跑一次） |
| `--source-style print` | 來源行改用【日期/媒體】【記者】體例 |
| `--no-doc` | 只產 .docx，不呼叫 Word 轉 .doc |
| `--list-history` | 列出歷史紀錄 |
| `--from-history <id>` | 由某筆歷史紀錄重新產檔 |
| `--no-history` | 這次不寫入歷史紀錄 |

輸出檔名自動組成 `年度_案號_統編_公司名`，例如
`115_A-I-001_54955208_台灣禾邦電子有限公司.doc`。

## 網頁版

```bash
streamlit run app.py
```

流程：左側輸入公司與案件資訊 → 開始蒐集 → 逐則檢視／勾選／就地修訂標題與內文
→ 產生 Word 檔並下載。

### 部署到 Streamlit Community Cloud

1. 把本資料夾推上 GitHub。
2. 到 <https://share.streamlit.io> 新建 app，選該 repo，主程式填 `app.py`。
3. 不需要任何 API key 或 secrets。

> **更新後若出現 `TypeError`**：Streamlit Cloud 在 repo 更新時會重跑主程式，但已
> import 的模組仍留在記憶體，造成 `app.py` 是新版、`crawler.py` 是舊版。程式已內建
> 版本檢查會自動重載；若仍出現，到右下角 **Manage app → Reboot app** 重啟一次即可。

雲端（Linux）沒有 Word，因此只會提供 **.docx** 下載；用 Word 開啟後另存新檔即可
轉成 .doc。在本機 Windows 執行時，程式會自動呼叫 Word 轉出 .doc 並更新目錄頁碼。

## 改完程式先跑冒煙測試

```bash
python smoke_test.py
```

檢查三個模組版本是否一致、`app.py` 的 `APP_VERSION` 是否同步，並用
`streamlit.testing` 把 `app.py` 實際執行一遍。

注意：`streamlit run` 起得來**不代表程式沒錯**——健康檢查在主程式執行前就回 200，
腳本要等瀏覽器連上才跑，所以光看啟動 log 抓不到 `NameError`、`ImportError`。

## 歷史紀錄

每次蒐集完成會自動存一筆紀錄（命令列版與網頁版都會），內容包含公司／年度／案號／
統編、使用的關鍵字與參數、來源分布，以及全部新聞的標題、網址、日期、來源、議題
標籤與全文。

儲存位置依序取用環境變數 `NEWS_CRAWLER_HISTORY`、程式資料夾下的 `history/`。
一筆紀錄一個 JSON 檔，沒有索引檔，多個程序同時寫入不會互相覆蓋。

### 網頁版

頁面最下方「📚 歷史紀錄」可以：

- **載回編輯**：把該次結果讀回上方清單，重新勾選、修訂後再產檔
- **下載 JSON**：單筆原始資料
- **產生 Word**：直接由該筆紀錄重出 `.docx` 並下載
- **下載全部（ZIP）**：所有紀錄的 JSON 加一份 `索引.tsv`
- **刪除**：移除該筆

> ⚠️ 雲端版的歷史紀錄存在伺服器暫存空間，**重新部署或重啟會清空**，而且同一個 App
> 的使用者都看得到。要長期保存請下載 ZIP；敏感案件請用本機版執行。

### 命令列版

```bash
python main.py --list-history                      # 列出所有紀錄
python main.py --from-history 20260826-103654_維格餅家股份有限公司   # 由紀錄重新產檔
python main.py --company ... --no-history          # 這次不寫入紀錄
```

## 產出版面

程式重建了原始 .doc 的樣式，名稱與規格皆一致：

| 樣式 | 用途 | 規格 |
|---|---|---|
| `廠商 - 目錄 標 1` | 章節標題「八.近兩年相關新聞」 | 標楷體 18pt 粗體，最小行高 20pt |
| `title2.0` | 新聞標題（目錄由此產生） | Microsoft YaHei 16pt 粗體，段前 12pt |
| `廠商 - 新聞來源` | 網址／來源標示行 | 標楷體 11pt |
| `廠商 - 新聞 2` | 文中小標 | 標楷體 13pt 粗體 |
| `廠商 - 新聞內容` | 內文 | 標楷體 13pt，左右對齊，固定行高 24pt，首行縮排 2 字元 |

目錄使用 Word 的 `TOC \h \z \t "title2.0,1"` 欄位，並已設定 `updateFields`，
用 Word 開啟時會自動更新頁碼（也可手動按 Ctrl+A 再按 F9）。頁尾置中頁碼。

## 新聞來源

**不限來源**：任何 Google News 收錄的媒體都會蒐集。以下優先序依既有的
`新聞來源彙整.xlsx`（30 家公司、194 則新聞的實際統計）設定，而且是**加權**不是門檻——
優先來源會排前面，但其他媒體只要夠新、夠相關一樣會排進來。

| 層級 | 來源 | 待遇 |
|---|---|---|
| 第一優先 | 經濟日報、工商時報、鉅亨網、公司官網 | 除全網檢索外另做**定向檢索**；排序時等於自動年輕 180 天（清單上標 ★） |
| 第二優先 | MoneyDJ、自由時報、聯合報、中央社、科技新報、DIGITIMES、財訊、今周刊、商業周刊、CMoney、中時新聞網、數位時代、iThome、遠見、公開資訊觀測站、Investing.com | 排序時等於自動年輕 60 天 |
| 其他 | 任何 Google News 收錄的媒體 | 照常蒐集，純依日期與關鍵字命中排序 |

加權天數可調：CLI 用 `--priority-boost 180`，網頁版用側欄滑桿。設 **0** 就完全不分
來源、純依日期排序。

實作方式：

1. **Google News RSS** 做全網檢索，再對第一優先網域各下一次 `site:` 定向檢索。
2. **鉅亨網搜尋 API** 直接取得全文。
3. **公司官網**：填入官網網址後，程式會找出「最新消息／新聞中心／Press」等列表頁，
   解析標題與日期後逐則抓全文。官網若是 JS 動態渲染（例如 Shopify 類購物站）靜態
   抓不到，會自動改用 `site:官網網域` 的定向檢索作為備援。
4. 來源名稱會依網域正規化成報告慣用的稱呼（`money.udn.com` → 經濟日報、
   `ctee.com.tw` → 工商時報、`news.cnyes.com` → 鉅亨網），官網則標成「○○官網」。

全文擷取順序：站台專屬選擇器 → JSON-LD `articleBody` → 段落密度最高的區塊；
之後再過濾廣告、推薦新聞、免責聲明等雜訊。編碼依「HTTP 標頭 → HTML meta → 逐一
試解並比較亂碼比例」判定，Big5／GB 網頁不會變亂碼。

## 檢索對象與關注議題

### 檢索對象

除受訪公司外，可另填**母公司（投資人）與相關企業／轉投資公司**，各自展開關鍵字
檢索。結果會標明是為哪一家找到的（清單上的〔公司名〕）。

- CLI：`--related "母公司全名,轉投資公司全名"`
- 網頁版：側欄「母公司／相關企業」，每行一家

### 關注議題

**議題同樣是加權不是門檻，不限於這些題材。** 命中議題的新聞在排序時每項扣 120 天
（最多計兩項）往前排；未命中議題的新聞照樣蒐集，而且會保留 **25% 的名額**優先給
它們，避免議題加權把一般新聞（法說會、營收、人事、市場行情等）整批擠掉。

| 參數 | CLI | 網頁版 | 說明 |
|---|---|---|---|
| 議題加權天數 | `--topic-boost 120` | 滑桿 | 設 0 = 不加權 |
| 其他題材保留名額 | `--other-quota 0.25` | 滑桿 | 設 0 = 不保留 |
| 只要議題新聞 | `--require-topic` | 勾選框 | 預設關閉；開啟才會真的過濾 |

注意 `AI`、`EV` 這類英數關鍵字採詞界比對，不會誤中 `said`、`chain`、`detail`。

## 已知限制

1. **付費牆**：經濟日報、工商時報部分內容需訂閱，抓到的可能只有前段。程式會在
   結果中標示字數，網頁版可直接補貼內文。
2. **議題標籤是關鍵詞比對，不是語意判讀**：文中順帶提到「美國」加上「產能」就會標成
   供應鏈轉移（北美），可能過寬。標籤用於排序與人工篩選，不應直接當成分析結論。
3. **Google News 網址還原**依賴 Google 內部介面，若 Google 改版可能失效；屆時
   仍會保留 Google 轉址連結，只是全文擷取會失敗（結果會標示錯誤訊息）。
3. **關鍵字命中不等於相關**：同名公司、只是順帶提及的新聞都可能入列，務必在
   網頁版逐則確認後再產檔。
4. 請遵守各新聞網站的使用條款；程式已內建請求節流（預設 0.8 秒），請勿調得過短。
